# Jo⚡Go Visual Standard

## Purpose

Prevent strong mechanics from being undermined by generic or sloppy presentation.

## Visual pipeline

1. prove the mechanic;
2. generate 3 distinct art directions;
3. choose one;
4. create menu/gameplay/alternate/results references;
5. extract a visual specification;
6. implement;
7. inspect close-ups of hero assets;
8. render at actual iPad size;
9. perform a targeted repair pass.

## Authoritative reference rule

Once approved, concept art is a visual source of truth for:

- composition;
- material language;
- palette;
- density;
- hierarchy;
- control styling;
- character tone;
- reward presentation.

Implementation may simplify assets for performance, but should not improvise a different art direction.

## Hero asset standard

A hero asset is an object central to play or learning: scale, ruler, snake, launcher, track, word tile, fraction model, etc.

Hero assets must:

- survive close inspection;
- avoid accidental overlaps;
- have consistent line/stroke logic;
- have strong contrast;
- clearly separate interactive/active parts;
- remain legible at 1024×768;
- animate in a way that clarifies state.

## Screen hierarchy

Every gameplay screen should answer within one second:

1. What should I look at?
2. What should I do?
3. What happened after I did it?

## Tactile UI

Controls should visibly respond to touch:

- press/depress;
- highlight;
- snap;
- pulse;
- fill;
- move.

Do not rely on hover for essential information.

## Visual QA checklist

- no clipped text;
- no overlapping labels;
- no dark-on-dark active elements;
- no inconsistent icon language;
- no decorative marks that can be mistaken for educational marks;
- primary focal object is dominant;
- feedback is visually distinct from instructions;
- UI does not become busier as difficulty increases.
